# SilicaFlow Agent Operating Contract

This repository is structured for AI-agent orchestration of bounded silicon design
tasks. Agents operate within explicit role boundaries, produce structured outputs,
and defer to human engineers at milestone gates.

## Three-Tier Model

| Tier | Role | Boundary |
|------|------|----------|
| **AI Orchestrator** | Sequences stages, interprets reports, proposes fixes | Cannot bypass human gates or edit PDK/lib files |
| **EDA Tool Agents** | Execute bounded tool invocations, produce JSON reports | Stateless — all state lives in the filesystem |
| **Human Engineer** | Approves gates, sets policy, overrides decisions | Final authority on all source-of-truth changes |

## Hard Rules

1. **Source-of-truth inputs** (`design/`, `config/`, `docs/`, `flow/`, `architecture/`, `product/`) — treat as controlled. Propose changes as patches; do not apply without validation.
2. **Disposable outputs** (`work/`, `logs/`, `reports/`) — freely writable. Regenerated by tool runs.
3. **External inputs** (`pdks/`, `libs/`) — read-only. Never edit in-place.
4. **No silent waivers** — do not waive lint, CDC, timing, DRC, or LVS issues without recording rationale in `docs/` or the relevant gate checklist.
5. **Validate every change** — every nontrivial change must end with the narrowest practical `make` target for that stage.
6. **Structured reports** — every tool invocation must produce a JSON report conforming to `schemas/tool_report.schema.json`.
7. **Gate enforcement** — the flow cannot advance past a human gate without explicit `make approve GATE=<name>`.

## Human Milestone Gates

These gates **block all downstream stages** until the human engineer approves.

| Gate | Question | Checklist |
|------|----------|-----------|
| 🔒 G1: spec_freeze | Are we building the right thing? | [G1](docs/gates/G1_spec_freeze.md) |
| 🔒 G2: rtl_freeze | Is the design functionally correct? | [G2](docs/gates/G2_rtl_freeze.md) |
| 🔒 G2b: custom_freeze | Are custom blocks verified and characterized? | [G2b](docs/gates/G2b_custom_freeze.md) |
| 🔒 G3: synth_handoff | Are we on PPA budget? | [G3](docs/gates/G3_synth_handoff.md) |
| 🔒 G4: tapeout | Is this ready for fabrication? | [G4](docs/gates/G4_tapeout.md) |
| 🔒 G5: package_release | Is the package integration sound? | [G5](docs/gates/G5_package_release.md) |
| 🔒 G6: test_signoff | Is this ready for production? | [G6](docs/gates/G6_test_signoff.md) |

```bash
make gates                        # Show gate status
make approve GATE=rtl_freeze      # Approve a gate
make reject  GATE=rtl_freeze REASON="CDC violations unresolved"
```

## Tool-Agnostic Dispatch

Every stage dispatches to a configurable tool backend:

```bash
# Default (open-source) tools
make lint                          # Uses verible
make synth                         # Uses yosys

# Override with commercial tools
make lint TOOL_LINT=spyglass_lint  # Uses Synopsys SpyGlass
make synth TOOL_SYNTH=genus        # Uses Cadence Genus
make sta_pre TOOL_STA=primetime    # Uses Synopsys PrimeTime
make drc TOOL_DRC=calibre_drc     # Uses Siemens Calibre
```

To add a new tool backend, create `flow/<phase>/<stage>/<tool_id>/run.sh` and register it in `config/tools.yaml`.

## Handoff Protocol

Every agent role file defines:
- **Receives From**: what inputs it expects from upstream agents
- **Delivers To**: what outputs it provides to downstream agents
- **Delivery Format**: file types, locations, and schemas

See `agents/roles/*.md` for the complete handoff matrix.

## Escalation Paths

When an agent encounters ambiguity or a decision beyond its scope:

1. **Surface the assumption** — never guess. Document what is unclear.
2. **Propose options** — present alternatives with tradeoffs.
3. **Escalate to the right agent** — use the handoff protocol to identify the owner.
4. **Escalate to human** — if inter-agent resolution fails, flag for human review.

## Prompting Pattern

When assigning work to an agent, provide:

- The **exact stage** and deliverable
- The **input files** or reports
- The **expected output** artifact
- The **validation command** (`make <stage>`)
- The **assumptions** that must be surfaced instead of guessed

See `prompts/` for reusable task templates with worked examples.

## Review Gates (per change type)

| Change Type | Minimum Validation | Gate Impact |
|-------------|-------------------|-------------|
| Product/requirements | Update traceability, acceptance criteria | May require G1 re-review |
| Architecture/budgets | Update interface contracts, verification plan | May require G1/G3 re-review |
| RTL/assertions | `make lint parse sim formal cdc` | May require G2 re-review |
| Constraints/SDC | `make synth sta_pre` | May require G3 re-review |
| Physical/PnR | `make pnr sta_post drc lvs` | May require G4 re-review |
| Tool wrappers | `make env` + narrowest affected stage | — |
| Package artifacts | Rerun affected analysis | May require G5 re-review |
| Silicon test | Rerun affected ATPG/ATE/characterization step | May require G6 re-review |
